# 穿衣推荐 Skill

## 目标

根据用户指定的地点和时间，先获取尽可能新的天气信息，再给出简洁、具体、可执行的穿衣建议。不要在没有天气依据时直接猜测。

## 标准流程

1. 确认地点和时间。
   - 用户没有提供地点时，先询问城市或地区。
   - 用户没有提供日期时，默认理解为今天；如果问题中使用“明天”“周末”等相对时间，明确换算成具体日期。
   - 不要把用户的当前位置当作已知地点，除非系统明确提供了位置。

2. 调用 `web_search` 获取实时天气。
   - 优先搜索：`<地点> <日期> 天气 温度 降雨概率 风力`。
   - 优先采用气象机构、天气服务或可信新闻来源。
   - 如果第一次搜索结果缺少温度、降雨或风力信息，再补充一次更精确的搜索。

3. 从搜索结果中提取以下信息：
   - 最高温度和最低温度；
   - 用户关注时段的体感温度（如果有）；
   - 降雨概率、降雪或雷暴信息；
   - 风力、阵风和体感偏冷信息；
   - 极端天气、空气质量或紫外线等会影响出行的提示。

4. 生成穿衣建议。
   - 先给一句结论，例如“建议春秋装，早晚加一件薄外套”。
   - 再按贴身层、中间层、外层和鞋子给出建议。
   - 早晚温差较大时，明确分时段说明。
   - 降雨概率较高时，提醒雨伞、防水鞋或防水外层。
   - 风力较大时，考虑防风外套；低温且有风时不要只依据气温判断。
   - 高温时提醒透气、遮阳和补水；寒冷时提醒保暖，但不要夸大风险。
   - 如果用户说明了性别、年龄、活动类型、是否骑行或是否怕冷，结合这些条件调整建议；没有说明时使用中性、普适建议。

5. 说明依据和不确定性。
   - 在答案中列出查询到的地点、日期、温度范围和关键天气因素。
   - 说明天气数据的来源或查询时间（搜索结果提供时）。
   - 如果搜索结果互相矛盾，说明差异，不要伪造精确数值。
   - 如果无法获得可靠实时数据，明确告诉用户，并给出基于已知信息的保守建议。

## 输出格式

使用以下结构：

```text
结论：<一句话穿衣建议>

天气依据：
- 地点/日期：...
- 温度：...
- 降雨/风力：...

具体建议：
- 上衣：...
- 外套：...
- 下装和鞋子：...
- 其他：...

提示：<早晚温差、降雨、强风或数据不确定性>
未来三天的天气预报：...
```

## 限制

- 不要声称自己读取了用户的实时定位，除非输入中明确提供。
- 不要把搜索摘要中的推测当成确定天气。
- 不要提供医疗诊断；对婴幼儿、老人或特殊健康状况，只能给一般性保守建议，并建议参考专业意见。
- 不要为了给出建议而调用 `shell`、写文件或修改数据库；本 Skill 只需要 `web_search`。
